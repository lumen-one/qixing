# 决定：记录与主线分家，各住一个文件

记录：2026-11-08
状态：生效中

## 问题

记录（日历上圈出来的段 + 月记）原来是主线的一部分：先是 `Mainline` 的字段，落在
`主线.md` 每条主线块里，记录页是主线覆盖页的第 2 页。三处耦合跟着来：

1. **归档即只读**——记录页的编辑权限跟着 `mainline.isActive` 走，一归档整页变灰，再也
   写不进去。可"这条不做了"和"今天不记了"是两件事；
2. **没主线就没有记录**——覆盖页在 `m == null` 时直接返回空态，连 PageView 都不建，
   页头那颗 `1/2` 也不显示。想记一笔，得先编一条主线；
3. **数据在别人家里**——记录段与月记存在主线块的正文里，主线一重写就得跟着一起保真。

## 决定

记录独立成一本册子：`LogBook`（`LogSegment` 列表 + `MonthNote` 列表），住
`tasks/记录.md`（[记录文件](../formats/logbook.md) B.10），服务与仓储都是独立的一套
（[记录插座](../sockets/logbook.md)）。`主线.md` 只剩行为链。

两页因此同等独立（[主线圈](../panels/mainline.md)、[记录页](../panels/record.md)）：

- 记录页**没有只读态**，归档一条主线不改它一行，看归档主线时翻过去也是这同一本；
- **没有主线也能进**：页头 `1/2` 常驻，第 1 页是空态（新建入口），左滑或点它就到记录页；
- 段不重叠的约束范围从"一条主线内"扩到"整本册子内"——只有一本，规则本身没变。

旧版 `主线.md` 里的 `### 记录` / `### 月记` 两段**不自动迁移**：解码时只留一条告警，
保存重写正文时丢掉，要留的内容由人自己搬。

## 备选与为什么输

- **记录仍存在主线块里，只把界面解锁**（去掉 `readOnly`、`1/2` 常驻）：最省事，但
  "没有主线时写一笔"没有容器可落——要么凭空造一条主线，要么写进一个不属于任何主线的
  幽灵块。前者是假数据，后者其实是新文件的一半。
- **记录按主线 id 分块存进新文件**：文件分家了，逻辑还拴在一起。归档主线照样会带出
  "这段记录属于一条已归档的主线"的只读判断，删主线还得处理孤儿段——想独立就独立干净。
- **做一次性自动迁移**（读旧段 → 写进 `记录.md` → 删旧段）：对用户最省心，代价是多一条
  只在升级那一次跑、却要长期留在代码里的路径，两个引擎同时启动还得处理竞争。实际数据量
  很小，人工搬一次就够，所以这次只留告警；出现"升级后记录没了"的抱怨再补。
- **记录做成面板的第五页**（灵感 / 今日 / 池子 / 已完成 / 记录）：它和主线是一对"现在推的
  事 / 这些天干了什么"，放在同一个覆盖页里翻页才连得上；面板页序那边的四页是任务的四种
  视图，塞进去反而要多一次跳转。

## 代价

- 升级那一下要人自己搬：不搬就等于作废，`主线.md` 下一次保存会把那两段删掉。
- 记录不再对得上主线：归档查看只能看行为链，"这条主线当时记了些什么"没有入口——这是
  独立换来的，不另做关联字段。
- 段不重叠的拒绝理由会跨主线出现：两条主线同时跑过的日子只留得下第一段。
- 多一个要同步的文件（`记录.md`），冲突规则与 `主线.md` 同档（后写者胜）。
