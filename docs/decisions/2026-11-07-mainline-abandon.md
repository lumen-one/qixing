# 决定：主线可以废弃归档，与完成归档并列

记录：2026-11-07
状态：生效中

## 问题

一条主线只有一个结束方式：行为链全部勾完 → 归档。可真实情况是"这件事不做了"——方向换了、
条件没了、想清楚了不值得。这类主线既不该继续占着顶栏（同时只有一条在跑），也不该被假装
勾完：勾完会写下一个假的完成时刻，归档列表里从此分不出"做完了"和"不做了"。删掉它更不行，
记录段和步骤是那段时间唯一的载体。

## 决定

`Mainline` 有两个归档时刻：`completedAt` 与 `abandonedAt`，两个都空才是在跑。完成仍然要求
行为链全部勾完，废弃不要求、也不写完成时刻。两者都只改状态、不删数据，归档后一律只读，
都不能恢复为当前。

`主线.md` 里就是多一行 `abandoned: <时刻>`；两个字段都有值（手改出来的边角）按完成算。

归档列表把两类并在一起，按归档时刻从新到旧排，一行一条：主线名 + 『已完成』或『已废弃』
徽标 + 归档日期，点一条进只读页。列表标题是『归档 · N 条』——里面已经混了两种结局，再叫
"已完成的主线"就不准了。

入口在标题行右侧，与『完成主线』同一个位置：没勾完时是『废弃』，勾完时是『完成』。这个
位置回答的是"这条主线结束了没有"，而结束只有两种方式，不会同时需要。

## 备选与为什么输

- **删掉不用的主线**：删了就没有记录段和完成时刻，而这段记录本来就是"我这段时间干了什么"
  的一部分；也给手滑开了一条不可逆的路。归档恰好是"丢掉进度、留下痕迹"。
- **加一个 `status` 枚举（active / done / dropped）**：时刻本身已经能表达状态（有值即归档），
  再加一个枚举就是同一件事的第二种说法，还要处理两者不一致的情形；文件里那个值是英文
  token，人打开 `主线.md` 得先记住词表才读得懂。
- **废弃也要求勾完**：那就等于没有这个功能。
- **允许恢复为当前**：同时只有一条在跑，恢复要先解决"现在那条怎么办"；而主线不是待办，
  重开一条重新写步骤，不见得比复活一条半途的更差。宁可少一条路径。
- **把废弃记在 `completed` 里、另加 `outcome: dropped`**：向下兼容最好（老版本只会当它
  已完成），代价是"完成时刻"这个名字从此名不副实，每个读它的地方都要多问一句"真的完成
  了吗"。为一个不常发生的降级场景，把日常代码的语义搞浑，不划算。

## 代价

- 老版本读新文件时，废弃的那条没有 `completed`，会被当成在跑（降级即错位）。不迁移、不
  兼容——登记在 [架构文档](../architecture.md) §11。
- 归档列表混了两种结局，扫一眼不再等于"我完成了什么"，要区分得看徽标。
- 勾完之后就没法再废弃（那颗图标变成了完成）。真要走这条路，先取消一步勾选。
