# 决定：闹钟是每件任务自己的开关，普通提醒一律有声

记录：2026-11-12
状态：生效中

## 问题

『响铃』（metadata `remind`）原本是"有声 / 静音"两态。它解决的是一个不太存在的问题：
提醒来了本来就该听见，默认就该响；真要安静，系统勿扰比逐条静音更顺手。反过来，真正的
痛点是"提醒来了没听见"——横幅一闪而过，人不在屏幕前就错过了。

旧的『闹钟模式』是个全局开关，只对开始型生效，语义是"把这一条升级成全屏闹钟"。它住在
设置页里，离具体任务很远：想给某一件加闹，得先知道有这么个全局模式。

## 决定

- 取消"静音"这一档：普通提醒一律通知栏 + 横幅 + 提示音 + 震动。
- 表单上的开关改名『闹钟』，metadata 换 `alarm`（只写 `true`，关掉即删键；缺键 = 不开）。
  它只对**时点提醒**生效：开始型到点、设了响的周期实例、无排序档的两站。标准档的截止型
  软提醒走通知栏，不摆这一行；已存的键保留但不生效，切回无排序档即恢复。
- 开着的那条到点起全屏闹钟页并**持续响铃**：默认 60 秒（`alarm_ring_seconds`，可选
  30 秒 / 1 分钟 / 2 分钟），到时自停，也能手动『停止响铃』。停声后通知留在通知栏、
  恢复成可划走。
- 权限缺失（全屏 / 锁屏显示）时不持续响，退化为通知栏 + 横幅 + 提示音。
- 旧设置『闹钟模式』改成『新任务默认开闹钟』（字段 `default_task_alarm`，读不到时回退旧
  `alarm_mode`）：它只决定创建表单的初值，不再进 `ReminderDispatcher` 的判断。
- 响闹钟时附一行"接下来还有什么"：未来 3 小时内其他开着闹钟的时点提醒，按时刻升序，
  最多 3 条。同一分钟的多条只起一个闹钟页，正文并排列出其余几件；那些件照常写
  `point_fired`、照常排下一站，不再二次响铃。
- 旧键 `remind` 退役：读取时忽略、不删不改。

## 备选与为什么输

- **保留三态（静音 / 普通响 / 闹钟）**：表单多一格，而静音这个需求已经由系统勿扰覆盖；
  多一个选项就多一次"我该选哪个"的犹豫。
- **沿用 `remind` 键改语义**：旧数据里 `remind: true` 是"要声音"，改读成"要闹钟"会让
  一批任务升级后突然全屏响铃。换键是一次性的迁移成本，误读是持续的事故。
- **软提醒也能开闹钟**：裕度提醒是"该动手了"，提前两小时全屏抢屏会让人直接关掉这个功能。
- **同一时刻只响一件、其余降级**：会吞掉本该提醒的件。改成"照响 + 互相在正文里露一面"，
  信息不丢，声音也不叠。
- **响铃时长做成逐任务可调**：一个全局值够用，逐任务调是没人会转的旋钮。

## 代价

- 旧的"静音"能力没了：开会时只能靠系统勿扰。
- 老任务升级后从安静变有声（以前缺 `remind` 按静音算，现在一律有声）。迁移不改人的
  数据，`remind` 键留着但不读。
- 响铃是新的原生实现：循环播放 + 前台服务 + wakelock + 全屏页，比原来"一条通知 +
  full-screen intent"重得多；应用被杀、锁屏、Doze 是三条要各自走通的路径。
- 桌面没有闹钟渠道：表单不摆这个开关、设置也不摆默认值与时长，但数据照写，同步到手机
  后才生效。
- 周期规则的『响』还是另一套（决定这个实例有没有提醒），与任务上的『闹钟』叠加使用；
  两个开关离得不远，解释成本还在。
