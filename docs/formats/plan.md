# B.7 `编排.md`（今日编排的时间轴）

**一个文件装所有日子**，与 `主线.md` 同族：应用维护整份，Obsidian 里可读可改，读进来
的改动生效，保存时正文按模型重写。

```markdown
### 循环

- 08:30 晨会
- 12:30 午餐休息

### 2026-11-04 ·循环

- 08:30 晨会
- 12:30 午餐休息
- 15:00 临时插进来的事

### 2026-10-22

- 09:30 项目评审
```

- **日期段**：一行 `### yyyy-MM-dd`（写 `##` 也认）开头一段，段内一行一条。段与段之间
  按时间倒序排，应用写回时自己维持这个顺序；
- **模板段 `### 循环`**：标题只有「循环」两字的那一段是每日循环的模板，段内一行一条，
  写法与日期段里的一模一样。没有这一段就是不循环；段里一条都没有等于没有（写回时不落）。
  模板段恒在最前，不参与三天的界面渲染——它只喂"今天 / 明天还没排就照着落一份"；
- **`·循环` 后缀**：段头写成 `### 2026-11-04 ·循环` 表示这一天是循环生成出来的。它只管
  一件事：那天被删空之后段还留着，不会被下一次生成补回来。**空段也照写**（普通日期段
  为空时不落段，带后缀的落）。抹掉后缀就是普通的一天，其余内容不受影响；
- **一条 = 时刻 + 标题**：`- HH:mm 标题`。行首第一个词形如 `H:mm` / `HH:mm` 就当时刻
  （写回补零），否则整行都是标题、时刻为空；
- **行序就是顺序**：文件里的行序就是界面的顺序。保存本身不排序；但界面上改时刻或新增
  一条时，那天会先按时刻升序排好（同一时刻保持原相对顺序、没有时刻的沉到最后）再写回，
  因此落进文件的是排过的那一版。拖动改出来的顺序原样保留，直到下一次这类改动；
- **同一天可以有重复的标题**：两条『午餐休息』是两条，不去重、不合并；
- 时刻越界（`25:00`）按"没有时刻"处理，原文留在标题里，不改写；
- **已知局限**（登记在此，不另做）：
  - 正文由应用重写：不属于日期段或条目行的自由文字，下次保存会消失；
  - 标题以时刻开头（把 `12:30 出发` 整句当标题）会被当成时刻——与 `tasks.md` 里的
    `创建` / `完成` 锚点是同一类边界；
  - 两个引擎同时改同一份文件按后写者胜（与 `routines.md`、`主线.md` 一致）。
