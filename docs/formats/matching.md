# B.3 两条文档怎么对上号（连接键 + 三档降级）· B.4 软删除

内核属性文档里记着 `digest` = **人类文档那一行的指纹**（只看人写的部分，复选框状态不计）。
读取时按下表配对，写回时把新的指纹记回去：

| 档  | 判据                                                           | 覆盖的情形                                     |
| --- | -------------------------------------------------------------- | ---------------------------------------------- |
| 1   | `digest` 相等                                                  | 稳态：应用自己刚写过的行                       |
| 2   | 任务名相等（副本里的 `title`）                                 | 首次接管（还没有指纹）、人只改了创建/结束/备注、**长期任务**（它没有指纹） |
| 3   | **位置配对**：两边剩下的数量**恰好相等**时，按创建先后一一配对 | 人把任务名也改了（指纹和名字都变了）           |

- **数量不等就用前两档，绝不硬猜**：宁可把这一行当新任务接管（新建一个属性文档），
  也不把内核属性挪到另一条任务头上；
- **长期任务没有 `digest`**：它的稳态配对走第 2 档（任务名相等），靠副本里的 `title`；
  人把名字也改了 → 第 3 档或按新任务接管（有提示、不静默），旧 id 的副本留在 `.gtd/` 里
  等人工处理。**老版本写下的副本没有 `title`**（编码从不写、解码一直在读），遇到它们
  只能走第 3 档；一次加载把 `title` 补上之后就回到第 2 档；
- `digest` 不等的已知情形会记一条 notice：`任务行在应用之外被修改，已按归属合并`；
- 人类文档里删掉一行、内核属性文档还在 → **保留属性文件 + 提示**，不静默删数据
  （文件即备份，删不删由人决定）。

### B.4 软删除

删除 = **内核属性文件移入 `.gtd/.trash/`** + **人类文档里那一行整行拿掉**：

```markdown
# 工作

- [ ] 交房租 %%创建 2026-10-01,09:00%% ##生活
```

- **原行不留在 `tasks.md` 里，也不留空行**：行被拿掉，因此产生的连续空行收缩成一个，
  删完文档立刻是干净的。留下的做法（`%%` 注释掉那一行）会让阅读视图里凭空多出一段
  看不见的空白，攒多了整篇都是空档；
- 原行、删除时的行号与删除时刻跟着进回收站文件本身（`deleted_line` / `deleted_line_no` /
  `deleted_at`，见 [sidecar.md](sidecar.md)），回收站页从这几个键读名字、备注与日期；
- 恢复 = 文件搬回 `.gtd/` + 按 `deleted_line_no` 把原行插回原位。原文一字不动 →
  指纹不变 → 配对照旧走第 1 档。行号越界、或那个位置已经不是任务行（删除后文档被
  改短、重排过）时，退化为"按第一个标签找同名小节、追加到末尾"；
- 老版本留下的 `<!-- gtd:deleted <id> --> %%原行%%` 注释行仍读得出来（回收站照样列得
  出名字），「清空回收站」时连同这些遗留行一起清掉；
- 「清空回收站」= 真删 `.gtd/.trash/` 内容。
